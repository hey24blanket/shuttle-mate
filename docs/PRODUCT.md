# 셔틀메이트 — 프로토타입 제품 설계 v1.1

## 제품 약속

“어디쯤 왔어요?”라는 전화를 줄인다. 보호자는 내 아이의 이동을 이해하고, 운전자는 다음 행동에 집중하며, 운영자는 예외를 빠짐없이 확인한다.

## 청사진에서 보강한 결정

1. **운행 수명과 위치 상태를 분리한다.** READY / RUNNING / PAUSED / COMPLETED / CANCELLED가 운행 수명이다. MOVING / ARRIVED는 현재 정차 단계다. GPS_LOST나 지연은 별도 속성이므로 위치가 끊겨도 승하차 진행 상태를 잃지 않는다.
2. **요청과 승하차 결과를 분리한다.** 지연 또는 장소 변경 요청이 탑승 완료를 덮어쓰지 않는다. SUBMITTED → SEEN(선택) → APPLIED / REJECTED로 처리하고, 보호자는 대기 중인 요청을 WITHDRAWN으로 취소할 수 있다. 이 버전은 승인과 오늘 운행 반영을 한 트랜잭션으로 처리하므로 승인됐지만 미반영된 중간 상태를 만들지 않는다.
3. **마지막 하차가 종료 조건이다.** 최종 목적지 도착, 모든 학생의 결과 처리, 탑승 중 인원 0명, 미처리 요청 0건을 모두 만족해야 운행을 종료한다.
4. **잘못 누른 기록도 남긴다.** 현재 정차지에서 승하차를 정정할 수 있다. 기존 이벤트는 보존하고 정정 이벤트를 추가한다. 이미 지난 정차지에서 임의 수정하지 않는다.
5. **변경의 영향 범위를 제한한다.** 장소 변경은 오늘 운행의 배정만 바꾼다. 기본 노선 저장은 현재 운행을 바꾸지 않는다. 신규 원생은 다음 운행부터 배정된다.
6. **지난 정차지와 중복 요청을 차단한다.** 현재 이후의 다른 탑승지만 변경 대상으로 표시한다. 진행 중 요청은 아동당 1개로 제한하고, 미처리 요청이 있는 아동은 탑승 처리 전에 확인한다.
7. **정보가 없으면 숫자를 꾸며내지 않는다.** 실제 도로 ETA를 흉내 내지 않고 정차지 진행과 예정 시각·운영자 입력 지연을 구분한다. 위치 수신 중단 시 차량 마커를 숨기고 불확실성을 알린다.
8. **보호자 화면은 자기 아이만 보여준다.** 다른 아동 이름·보호자·승하차 이벤트를 화면에서 제외한다. 이는 프로토타입의 표시 범위이며 실제 보안 경계는 서버 인증/권한으로 구현해야 한다.

## 화면과 완성한 체험

| 역할   | 화면            | 가능한 행동                                                                                |
| ------ | --------------- | ------------------------------------------------------------------------------------------ |
| 운영자 | 오늘의 운행     | 운행·탑승·요청·지연 확인, 요청 승인/반려/확인 중, 상세 명단, 종료 후 새 운행 생성          |
| 운영자 | 노선 관리       | 순서 드래그 또는 위아래 이동, 이름/시각 편집, 정차지 추가, 기본 노선 저장                  |
| 운영자 | 원생 관리       | 원생·보호자 검색, 탑승지 필터, 원생 등록                                                   |
| 운영자 | 운행 기록       | 운행/승하차/요청별 필터, 검색, CSV 다운로드                                                |
| 운영자 | 운영 설정       | 기관명 변경, 지연 시간, GPS 끊김 체험, 초기화, 조건부 운행 취소                            |
| 운전자 | 메트로 타임라인 | 시작, 도착, 탑승/미탑승, 정정, 출발, 일시 정차/재개, 최종 하차, 종료                       |
| 보호자 | 오늘의 안심     | 내 아이 상태, 경로, 결석/직접 이동/지연/장소 변경 요청, 요청 취소, 처리 결과, 내 아이 기록 |

## 권장 체험 시나리오 (약 5분)

1. 보호자 화면에서 서아의 탑승지를 망원초등학교로 변경 요청한다.
2. 운영자 화면에서 요청을 승인한다. 보호자 화면의 오늘 탑승지는 바뀌지만 원생 기본 탑승지는 유지된다.
3. 기존 박도윤의 장소 변경 요청도 처리한다.
4. 운전자 화면에서 도착 → 아동별 탑승 확인 → 출발을 진행한다. 미처리 아동이 있으면 출발할 수 없다.
5. 센터에 도착한 후 종료를 눌러 본다. 탑승 중인 아동이 있으면 종료할 수 없다.
6. 전원 하차를 확인하고 종료한다. 보호자 화면에서도 완료·위치 공유 종료를 확인한다.
7. 운행 기록을 내보내고 새 운행을 생성한다. 요청과 아동 상태가 깨끗하게 시작되는지 확인한다.

## 체험 데이터와 운영 서비스의 경계

- 본 배포는 가상 아동 8명, 정차지 5곳, 차량 1대의 등원 운행 프로토타입이다.
- localStorage로 새로고침 후 상태가 보존되고 storage 이벤트로 같은 브라우저의 탭에 반영된다. 동시에 여러 기기에서 사용하는 서비스가 아니다. 브라우저 탭의 완전 동시 쓰기에 대한 분산 동시성 보장은 없다.
- 역할 전환은 체험용이며 인증이나 접근 제어가 아니다. 클라이언트에 모든 가상 데이터가 있다. 실제 개인정보를 입력하지 않는다.
- 지도에서 실제 위치와 예시 노선을 분리한다. 실제 위치는 휴대폰 좌표이며 OpenStreetMap에 표시한다. 예시 노선은 별도 도식으로 실제 도로 경로/ETA가 아니다. 정차지 추가 시 예시 좌표를 사용한다.
- v1.2에서 실제 휴대폰 GPS와 OpenStreetMap 지도를 추가했다. 백그라운드 추적, 문자/푸시, 지도 검색, Firebase 연결은 포함하지 않았다. 기존 운영 DB와 외부 키는 사용하지 않는다.
- 설치 메타데이터/아이콘은 제공하지만 서비스 워커와 오프라인 앱 실행은 구현하지 않았다. 이미 열린 화면의 변경은 오프라인에서도 브라우저에 저장된다.
- 재시작 시 이전 이벤트는 목록에 보존되나, 별도의 영구 운행 이력 DB는 아니다. 초기화하면 체험 기록도 지워진다.

## 실제 운영으로 확장하는 순서

1. 조직/역할/보호자-아동 관계를 서버에서 인증한다. 개인별 read model을 제공해 보호자에게 다른 아동 데이터를 전송하지 않는다.
2. 상태 전이를 서버 트랜잭션으로 옮긴다. version 기반 충돌 방지와 idempotency key로 재시도 중복을 차단한다. `lib/trip.ts`의 규칙과 테스트를 재사용한다.
3. 승인/승하차 이벤트와 푸시 발송을 outbox로 연결한다. 푸시 실패가 상태 저장 실패로 이어지지 않게 한다.
4. 국내 지도 사업자 하나를 선택하고 서버에서 장소 검색·ETA를 처리한다. GPS last-seen·accuracy 기준의 stale 판정을 추가한다.
5. 운전자/학부모 실제 단말로 화면 꺼짐, 앱 전환, 네트워크 단절, 재연결, 중복 누름과 하차 종료를 현장 검증한다.
6. 조직별 운영일·왕복 노선·대기 정책·개인정보 보존기간과 비상 연락 절차를 운영자와 결정한다.

AI, 결제, 대형 배차 최적화는 이 핵심 루프가 현장에서 검증된 뒤 검토한다.
